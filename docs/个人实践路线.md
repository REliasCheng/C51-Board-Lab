# 实践扩展设计

当前公开仓库只包含维护者编写的 Board Resource Planner、主机端测试和板级技术文档，不包含历史 `course/` 源码、旧 Keil 工程或厂商 SDK。

## 当前实现路线

```text
Board module definition
        ↓
Resource bitmap mapping
        ↓
Explicit planning result
        ↓
Deterministic conflict details
        ↓
Host failure-path verification
```

规划器负责在组合工程编码前识别静态 GPIO、Timer 与显示模式重叠。它不驱动真实外设，也不替代具体板卡的原理图、跳线和电气检查。

## 后续候选方向

以下内容仅是未来独立实现方向，当前仓库未提供对应驱动或验证结果：

1. DS1302：区分一次性校时与正常读取，并向上层传播失败；
2. UART：接收路径使用有界缓冲，解析和发送留在主循环；
3. AT24C02：增加 ACK、写完成轮询、超时和错误返回；
4. 按键：使用周期扫描与边沿事件；
5. 显示：使用固定周期刷新，应用层只更新显示缓冲区。

任何后续实现都需要独立源码、可复现构建和与其证据范围匹配的验证记录，不能从未公开的历史课程工程恢复内容。

## 综合应用结构

板级状态终端可以按以下数据流规划：

```text
Keys / ADC / RTC
        ↓
Application state
        ↓
Seven-segment or LCD
        ↓
AT24C02 configuration
```

这只是资源规划方向，不是当前已完成的固件或硬件运行证据。
